# Conversion corpus

Documents the `corpus` tool (`tools/corpus/`) converts with the x2t of an
installed build, through the same Rust code the app runs: open to the editor
format, save back to the original format, and export to PDF. The workflow
`.github/workflows/corpus.yml` runs it against a Build & Release installer.

`manifest.tsv` lists every document, its class, the steps to run, the text its
PDF must contain (`expect`, phrases separated by `|`; or `fail:<step>:<exit
code>` for a step that must fail with that code), the variants and the extra
formats to save as.

## Origin and license

Every file here was created for this corpus by the project on 2026-10-18 and is
covered by the repository license (AGPL-3.0, see `LICENSE`). None comes from a
user's file. They are rebuilt from the sources in `src/`:

```
sh tests/corpus/src/make-fixtures.sh
```

- The DOCX, ODT, ODS, ODP, XLSX and PPTX files are exported by LibreOffice
  7.3.7.2 (`soffice --headless --convert-to`) from the flat ODF sources in
  `src/` (`.fodt`, `.fods`, `.fodp`). Nothing is edited by hand afterwards.
- The image in `rich.docx` and `slides.*` is generated by `src/shapes_png.py`.
- The CSV and TXT files are written byte for byte by `src/text_fixtures.py`.

`.gitattributes` marks `tests/corpus/**` as `-text`, so a checkout never
changes their line endings.

## Classes

- `comparable`: uses only the fonts the app bundles (Liberation Sans, Serif and
  Mono, Carlito), so its results must match on every platform.
- `system-fonts`: depends on fonts of the machine that runs it. It is converted
  and reported the same way, but never compared between platforms.

LibreOffice 7.3.7.2 replaces Liberation Sans, Liberation Serif and Carlito with
Arial, Times New Roman and Calibri when Calc and Impress export OOXML (Writer
does not), whatever the source asks for. So `sheet.xlsx` and `slides.pptx` name
Microsoft fonts and are `system-fonts` even when rebuilt: they test importing a
spreadsheet and a presentation made by another program. The comparable
spreadsheet and presentation are `sheet.ods` and `slides.odp`, from the same
sources; the corpus saves them as xlsx and pptx with x2t, and each run checks
the font names in those files. If one names any other font, that row is
reported as `system-fonts` instead of comparable.

## Files

| File | Class | Covers |
|---|---|---|
| `@templates/blank.docx`, `.xlsx`, `.pptx` | comparable | the installer's own templates (default font of each editor; what a 0-byte file opens) |
| `liberation-carlito.docx` | comparable | one paragraph per bundled face (4 families x regular, italic, bold, bold italic), each with its expected text: a PDF that comes out without text fails |
| `justified.docx` | comparable | line breaks of a long justified paragraph in Liberation Serif 11 pt |
| `amp-name.docx` | comparable | copied at run time under names with `&`, `<` and `>` (file, folder and temp folder) |
| `metadata.docx` | comparable | title, subject, keywords and author survive a save; records what x2t writes as the application |
| `rich.docx` | comparable | table, header, footer, footnote, numbered and bulleted lists, headings, PNG image |
| `cyrillic-greek.docx` | comparable | Cyrillic and Greek text in Liberation |
| `sheet.ods` | comparable | formulas with cached results, dates, percent, currency and thousands formats, two sheets, merged cells; also saved as xlsx and csv |
| `sheet.xlsx` | system-fonts | the same sheet as LibreOffice exports it |
| `slides.odp` | comparable | two slides with different layouts, an image, speaker notes; also saved as pptx |
| `slides.pptx` | system-fonts | the same slides as LibreOffice exports them |
| `basic.odt`, `basic.ods`, `basic.odp` | comparable | ODF import and save |
| `utf8-bom-semicolon-crlf.csv` | comparable | UTF-8 BOM, `;`, CRLF, final break |
| `utf8-comma-lf-final.csv` | comparable | UTF-8 without BOM and with a final break: opened from the read copy without that break |
| `utf8-comma-nofinal.csv` | comparable | no final break, so no read copy |
| `win1252-semicolon.csv` | comparable | windows-1252 accents and ñ |
| `utf16le-tab.csv` | comparable | UTF-16 LE BOM and tab delimiter |
| `quoted-delimiter.csv` | comparable | quoted fields holding `;` and doubled quotes |
| `empty-lines.csv` | comparable | an empty line in the middle |
| `utf8.txt`, `win1252-crlf.txt`, `utf16be.txt` | comparable | TXT encodings and line endings put back after a save |
| `utf16le-crlf.txt` | comparable | TXT in UTF-16 LE with a BOM and CRLF, as Notepad saves "Unicode": opened from a UTF-8 copy and saved back to UTF-16 |
| `@empty:empty.docx` | comparable | a 0-byte docx opens the blank template and saves to its own name |
| `@empty:empty.csv` | comparable | x2t refuses an empty CSV: `expect` is `fail:open:88`, and only exit 88 on open counts as the expected failure |
| `cjk.docx` | system-fonts | Chinese and Japanese |
| `arabic-rtl.docx` | system-fonts | Arabic, right-to-left paragraph |
| `hebrew.docx` | system-fonts | Hebrew, right-to-left paragraph |

`@templates/...` rows read the template from the installer under test;
`@empty:...` rows are 0-byte files created at run time.

## Running it

`report` extracts the PDF text and fonts with poppler-utils (`pdftotext`,
`pdfinfo`, `pdffonts`) and unpacks the saved packages with `unzip`, so it runs
on Linux. On a Windows runner the unpacking would need `tar -xf` or
`Expand-Archive` instead.
